# AGENTS.md

## Runtime & tooling

- **Bun only** — use `bun`, never `node` or `npm`. Package lock is `bun.lock`.
- Vite commands are launched with `bunx --bun`. Install with `bun install`.

## Commands

| Command              | What it does                                   |
| -------------------- | ---------------------------------------------- |
| `bun run dev`        | Dev server                                     |
| `bun run build`      | Production build into `build/`                 |
| `bun run check`      | Type-check via `svelte-check` (syncs `.svelte-kit/` first) |
| `bun run lint`       | Prettier check + ESLint                        |
| `bun run format`     | Prettier write                                 |
| `bun test`           | Run tests (Bun's native runner)                |
| `bun run db:push`    | Push Drizzle schema to DB                      |
| `bun run db:migrate` | Run Drizzle migrations                         |
| `bun run db:studio`  | Open Drizzle Studio                            |

- `svelte-check` **requires** `.svelte-kit/tsconfig.json` to exist (generated by `svelte-kit sync`). The `check` script handles this; if running `svelte-check` manually, run `svelte-kit sync` first.
- The `prepare` script (`svelte-kit sync || echo ''`) runs after `bun install` and may silently fail — that's intentional for CI/build environments without a DB.

## Architecture

SvelteKit 2 app with `svelte-adapter-bun`, Tailwind CSS v4 (via Vite plugin, not PostCSS), PostgreSQL + Drizzle ORM, MinIO for file storage.

```
src/
  lib/
    events.ts              — shared event type enum (FRIEND_REQUEST, CAPTURE, WEBRTC, ...)
    server/
      auth.ts              — session-based auth (oslojs crypto)
      db/index.ts          — Drizzle client + pg LISTEN/NOTIFY → EventStore
      db/schema.ts         — Drizzle schema (user, session, friend, event, matchup, file, block)
      process.ts           — ImageVideoProcessor (sharp + ffmpeg merging)
      push.ts              — web-push notifications
      s3.ts                — MinIO/S3 upload helpers
      store.ts             — in-memory EventStore for SSE fanout
      rate-limit.ts        — in-memory rate limiter
      util.ts              — misc helpers
    client/
      events/              — client-side SSE event handling
      messages.svelte.ts   — reactive messages state (Svelte 5 runes)
      toast.svelte.ts      — toast notification state
      Modal.svelte         — modal component
      glsl.ts / util.ts    — WebGL helpers
  routes/
    (authenticated)/       — layout group gated by auth
    login/ logout/ register/ health/ debug/  — public routes
```

- `$lib` is aliased to `src/lib` (standard SvelteKit).
- Real-time events: PostgreSQL `NOTIFY new_notification` → `EventStore` (in-memory) → SSE stream to clients.
- Docker runs the built app at port **3000**. The `health/` endpoint is used for Docker health checks.
- `OUTPUT_DIR` (default `/tmp/buddycam`) holds processed media files.
- Sentry is conditionally enabled via `SENTRY_DSN` env var. Source map upload requires `SENTRY_AUTH_TOKEN`.

## Code style

- **Tabs** for indentation, single quotes, no trailing commas, 100 char width.
- Unused variables prefixed with `_` are allowed (ESLint `@typescript-eslint/no-unused-vars` with `argsIgnorePattern: '^_'`).
- Tailwind utility classes; the app font is "Bubblegum Sans".
- Prettier plugins: `prettier-plugin-svelte`, `prettier-plugin-tailwindcss`.

## Database

- Drizzle ORM with PostgreSQL. Schema at `src/lib/server/db/schema.ts`.
- Migrations in `drizzle/` are forward-only SQL files.
- `DATABASE_URL` must be set for `drizzle-kit` commands and at runtime.

## Testing

- Bun native tests (`bun test`). Single test file: `tests/rate-limit.test.ts`.
- The rate-limiter is purely in-memory; tests import directly and call `clearRateLimitsForTesting()` in `beforeEach`.
- No integration test harness exists — all tests are unit tests.

## Deployment

- `docker compose up -d --build --wait` (must use `compose` plugin, not the old `docker-compose` script).
- `deploy.sh` handles fast-forward pull + Docker rebuild + optional local stash.
- The compose file expects an external Traefik network (`traefik_web`) and uses `HOST_DOMAIN` env var for routing.
- Container runs read-only with a `tmpfs` at `/tmp`.
